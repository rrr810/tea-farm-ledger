# AGENTS.md: rules for any AI or developer working in this repo

## Money and weights
- Money is integer minor units (KES cents). Weights are integer tenths of a kg. Never use floating point for either.
- Pay is calculated per date at the rate in force that day, summed with integer math, then rounded ONCE per worker per week, half-up, to whole KES. The grand total is the sum of the rounded worker amounts.
- The pay calculation lives in packages/core and is shared by the server and the offline PWA. Do not duplicate it.

## Data integrity
- History is append-only. Never update or delete events, entries or payroll history. A correction is a new event or an adjustment line.
- Sync is idempotent by event_id. Re-sending must have no effect.
- The server is authoritative for lock state. Late events for a locked week are stored and flagged, never silently applied.
- Never silently resolve same-worker/same-day conflicts.
- Scheduled jobs must be idempotent: a restart must never double-send an SMS.

## SMS
- GSM-7 characters only. Single SMS 160 chars, concatenated segments 153 chars each.
- All SMS text is generated by the server from stored data. No hand-typed figures.
- Use the mock adapter by default. Follow Africa's Talking's official docs for the real adapter; do not invent API behaviour.

## Privacy and security
- Collect the minimum: worker name and mobile number only. No national ID numbers.
- No secrets in the repo. Environment variables only; keep .env.example current.
- Every change is attributable (author, device, time) in the audit log.

## Testing and process
- Tests are written with the feature. Never weaken, skip or delete a failing test to make it pass.
- Integration tests use a real test PostgreSQL database.
- Small commits, one branch per milestone, merge to main only when typecheck and all tests pass.
- Record unclear choices in docs/DECISIONS.md (what, why, alternative).
- No unrequested features. Phase 2 (payouts, SMS approvals, bonuses, USSD) is hooks only.
